# Packaged Grok explorer trial — November 5, 2026

## Outcome

The workbench has a reusable native TSX export and locally verified interaction
framework. Native packaged delivery remains blocked at source transport. This
report is distinct from the [earlier assistant-authored Page trial](2026-11-05-grok-interactive-charts.md),
which visibly rendered and responded in Grok Bot.

## Scope and implementation

The follow-up request was to make Grok's interactive charts consistent and closer
to Muse, establishing the framework before a later design/copy pass. Work stayed
on an isolated local feature branch. The native Mac Grok Bot conversation was
reused, while all new exported observations were generated synthetic data.
Existing personal Pages, archives, installed environments and scheduled jobs
were not changed. No push, merge or public sharing occurred.

`widget sleep-recovery --host grok` creates one self-contained `.canvas.tsx` file.
Its snapshot is identical to Muse's shared read transaction, including the
midpoint comparison and independent metric coverage. The renderer uses
`grok/canvas`, local React state and inline SVG. It adds no production dependency
or Crumb harness extension. Themes and view components are explicit places for
the later visual pass.

The initial foundation includes linked sleep/stages, HRV, resting heart rate,
score and daily Body Battery charge; Trends, Night detail and Compare; Last 7;
keyboard/pointer selection; segmented gaps; independent missing and failed
fields; and provenance/freshness details. Selection is temporary and observations
are fixed. Refreshing dates requires another export.

## Native contract and transfer trials

Grok reported that a native Page must be one self-contained module with only
`grok/canvas` imports and a default `App` export. Its `Page` takes a title;
`Section` takes an optional heading; `useGrokTheme().kind` selects light/dark.
The packaged renderer follows that reported contract, but native compilation
has not verified it.

The writer requires full inline `contents`. Its rejection of `$file:` references
was visible in the conversation. Grok reported that its supported file tools and
Shell could read/hash the source but could not bind file bytes directly to this
first-party writer. No undocumented API or credential workaround was used.

| Attempt | Input | Observed/reported result |
| --- | --- | --- |
| Original packaged source | 14 synthetic dates; 63,798 bytes | File reference rejected; no Page or compiler result |
| Supported bridge investigation | Existing file/tool capabilities | Grok reported no file-to-writer binding |
| Normal inline authoring | Final two-date synthetic source; 48,146 bytes | Grok reported invalid JSON, unterminated string at position 20,379; no Page or compiler result |

The final attachment hash was independently calculated locally and matched the
hash Grok reported: `544f308a5156da08df01f6d34af8bc449ba6f95f936f7ad178abae5b19e7fdd0`.
That verifies input identity, not saved Page identity. The inline attempt was
explicitly permitted to copy the full literal; its failure was not solely a
restriction against copying source. The truncation position is not treated as a
documented vendor limit. No saved source existed for `ReadCanvas` comparison.

## Local verification

- **Passed:** all 190 offline tests, including eight Grok exporter tests.
- **Passed:** guide checks and focused exporter rerun after delivery wording changed.
- **Passed:** package build and installed-wheel smoke checks with and without
  charts, including the packaged TSX export from outside the source checkout.
- **Passed:** 72 browser assertions using exact exported sources through a local
  React shim at widths 390/728 in light/dark themes. This is not the Grok SDK.
- **Passed:** inspected narrow Trends, Night detail and Compare plus wide dark
  Compare captures. Chart lanes align, selected values are legible, comparison
  columns fit, score differences use points, and no horizontal overflow appeared.
- **Not run:** native compiler, packaged Page interaction, physical-phone touch,
  cross-device delivery or reopen behavior. Transfer failed before those stages.

Browser checks cover linked selection, drag, slider and tab keyboard focus,
emulated touch, shared comparison values and coverage, warnings for either
incomplete period and current/future dates, failed observations independent of
sleep, valid zeroes, missing middle-date gaps, incomplete stages and 1/90-day
ranges. No HTTP(S) requests or runtime errors occurred. Full source hashes and
screenshots are generated by the repeatable harness in [testing](../TESTING.md#grok-renderer-harness).
Generated evidence stays outside tracked source.

## What brings this closer to Muse

The workbench now owns a consistent layout and behavior rather than asking Grok
to redesign each result. The remaining first step is a supported source handoff
and exact saved-source verification. A writer file/upload input or supported
output-to-input binding would remove model reproduction from transport. A
smaller projected payload/source is an alternative experiment, with separate
fidelity tests; it is not yet implemented or accepted.

After native compilation and interaction pass, refine the shared date hierarchy,
type and spacing scale, selected cursor, stage colors, chart density, focus and
touch targets, and concise source/status copy. Review inside the actual native
Page as well as the local harness. The current screenshots are a functional
foundation, not a claim of final polish or Muse feature parity. Grok's packaged
view has no persistent selection bridge, unlike the Muse widget.
