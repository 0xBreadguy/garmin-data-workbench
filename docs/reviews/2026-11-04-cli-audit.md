Scope: executable-only agent discovery and the complete 26-command CLI tree, starting from main `10672e4b481c39d7a2451ca4e9803873d0467bc2`. Offline synthetic work only. The Grok/Muse post-merge retest reports were read from Git objects `e6dab7e` and `310430d`; neither was imported or edited. ## Findings and changes

| Priority | Observed gap | Change and user benefit |
| --- | --- | --- |
| Medium | Baseline validates several sync/setup options after constructing the writable archive. Invalid intervals, nonfinite pauses and catch-up/end conflicts can therefore initialize storage before rejection. | A local preflight rejects these inputs, noninteractive setup without an explicit choice, and invalid key timeouts before archive construction/authentication. Actionable JSON errors, exit 2, empty stdout. Internal sync/install checks remain for direct callers. |
| Medium | Default argparse errors repeat invalid commands, choices, unknown arguments, float values and explicit flag values. A pasted private value can reach terminal logs. | Redact these values while preserving known argument names, allowed choices and help instructions. Tests cover pasted-value cases; this is input-diagnostic protection, not a claim that all application output is secret-free. |
| Medium | IDs/offsets can exceed SQLite's signed integer range and raise uncaught overflow; activity/record limits previously had no upper bound. Earliest-date implicit ranges can underflow. | Reject oversized integers and bound activity/record pages to 10000, retaining defaults and list formats. Native pages retain their existing 100-item bound. Reject impossible default date windows; handle remaining query overflow without a traceback. Large exports can continue with offsets. |
| Medium | An agent can find metric choices in `trend --help`, but units/titles/datasets require querying an archive or reading source. The retests also illustrate confusion about which installed revision is used. | Add archive-free JSON `metrics`, derived from shared metric definitions, and `version`, reusing existing installation provenance. Add conventional plain `--version`. No second metric mapping or build provenance mechanism. Package version alone is explicitly insufficient to identify a revision. |
| Low | Help gives little orientation about command side effects; native source selectors and global option placement are easy to miss. CLI date parsing accepts compact/week dates despite the documented ISO calendar format. | Root help provides a safe starting route, effects and exit-code summary. Detailed help links back to installed guidance/discovery; selectors, pagination and coordinate opt-in are explicit. Enforce exact `YYYY-MM-DD`, matching shared query semantics. USAGE explains historical bounds, source/display units, POSIX/PowerShell quoting and launcher stderr. |

Reproductions suitable for a disposable synthetic environment: `metrics`, `version`, `trend --help`, `source-data --help`; `sync --pause nan`, `setup --every-hours 169`, `records 9223372036854775808`, `activities --limit 10001`, `trend steps --to 0001-01-01`, `source-data sleep`, and `status --data-dir SOMEWHERE`. The invalid cases now exit 2 without creating an archive or using credentials. Tests invoke mutation-command rejection paths with archive/auth/schedule operations blocked; they are not live smoke commands.

Compatibility changes are intentional: compact/week dates, pages over 10000 and integers beyond SQLite's range now fail early. Valid default requests, query envelopes, bare activity/record lists, CSV, missingness and exclusive exports retain their formats. `--data-dir` remains before the command; help/errors teach this existing convention rather than adding two competing option locations.

## Retained behavior and deliberate deferrals

- Native fields and complete source coverage already have `api-catalog`, JSON Pointers, bounded `source-data` and `source-series`; no new generic command/plugin schema is justified. Actual parser `COMMAND --help` remains the flag authority. `metrics` is a small finite catalog, not a new registry.
- Raw `health` intentionally preserves stored responses, including retained failed-refresh data. Help directs normal interpretation to `--metadata`; changing its payload would break a useful local raw-data interface. Raw health/status/full FIT responses can be larger or more sensitive than bounded summaries. No silent truncation or coordinates added to defaults.
- Missing/empty/corrupt archives and failed refreshes already have meaningful distinctions and read-only tests; no automatic initialization, repair or implicit sync was added. Interactive cancellation and later setup runtime failures can still leave initialized setup state. A transactional installer rewrite is not warranted by these retests.
- Source timestamps/profile zone and units remain in shared query code. No CLI override/conversion engine, timezone inference, metric redefinition, dependency, schema, scheduler or MCP import/thread change.
- **Chart integration:** the separate chart branch commit `8bf289009c8d36e59b2798e627d7efb2d930beeb` owns optional `chart --json`. Preserve its parser/dispatch and USAGE qualifier: default confirmation remains; JSON emits shared metadata plus supplied `output_path` and CLI delivery text only after successful exclusive save. Failure stdout stays empty. This branch does not implement that flag. Common argument preflight also applies to chart dates; reconcile adjacent edits without losing either behavior. Installed help will expose the flag after integration.
- Existing-install handoffs, numerical interpretation and demo-date guidance remain with their assigned owners. Guidance can improve discovery but cannot guarantee a third-party assistant follows it. Final combined release checks and acceptance remain coordinator work.
